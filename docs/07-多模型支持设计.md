# 多模型支持设计方案

## 需求概述

支持配置多个 API 提供商（OpenAI、Claude、Gemini、DeepSeek 等），用户在设置中选择当前使用哪个提供商。

## 设计思路

### 核心变更：从"两种类型"到"可扩展的提供商列表"

当前架构只支持 `custom` 和 `ollama` 两种硬编码类型。改造为可扩展的提供商注册机制。

## 二、请求适配器

创建 `lib/api-adapter.js`，封装不同提供商的请求/响应差异：

```javascript
class ApiAdapter {
    constructor(provider, config) {
        this.provider = provider;
        this.config = config;
    }

    // 构建请求头
    buildHeaders() { ... }

    // 构建请求体
    buildRequestBody(messages, options) { ... }

    // 解析流式响应块
    parseStreamChunk(chunk) { ... }

    // 判断流是否结束
    isStreamEnd(data) { ... }
}
```

### 请求体格式对照

| 格式 | 提供商 | 特点 |
|------|--------|------|
| `openai` | OpenAI, DeepSeek, 自定义 | `{ model, messages, stream, max_tokens }` |
| `anthropic` | Claude | `{ model, messages, stream, max_tokens }` + system 单独字段 |
| `gemini` | Google | `{ contents: [{parts}], generationConfig }` |
| `ollama` | Ollama | `{ model, messages, stream, options: {num_predict} }` |

### 响应解析对照

| 格式 | 提取内容的路径 |
|------|---------------|
| `openai` SSE | `data.choices[0].delta.content` |
| `anthropic` SSE | `data.delta.text`（event: content_block_delta） |
| `gemini` JSON | `data.candidates[0].content.parts[0].text` |
| `ollama` NDJSON | `data.message.content` |

```javascript
    // 通用设置（不变）
    maxTokens: 2048,

    enableContext: true,
    maxContextRounds: 3,
    systemPrompt: '...'

```

### 向后兼容

迁移逻辑：检测旧格式 `apiType` + `custom_apiKey` 等字段，自动转换为新格式。

## 四、设置页面 UI 改造

### 提供商选择

将当前的下拉框改为卡片式选择器或标签页：

```
┌─────────────────────────────────────────┐
│  [OpenAI] [Claude] [Gemini] [DeepSeek]  │
│  [Ollama] [自定义]                       │
├─────────────────────────────────────────┤
│  API 密钥: [________________] 👁        │
│  请求 URL: [________________]           │
│  模型:     [▼ gpt-4o-mini    ]          │
│                                         │
│  [保存并测试]                            │
└─────────────────────────────────────────┘
```

### 模型选择

- 预设提供商：下拉框展示预设模型列表 + 支持手动输入
- Ollama：自动获取已安装模型列表（`GET /api/tags`）
- 自定义：纯手动输入

## 六、实现优先级

1. **Phase 1** — 重构存储结构 + 向后兼容迁移
2. **Phase 2** — 实现 ApiAdapter，支持 OpenAI/DeepSeek（同格式）
3. **Phase 3** — 添加 Claude 适配（不同认证方式和响应格式）
4. **Phase 4** — 添加 Gemini 适配（完全不同的 API 格式）
5. **Phase 5** — 设置页面 UI 改造
6. **Phase 6** — Ollama 动态模型列表获取
