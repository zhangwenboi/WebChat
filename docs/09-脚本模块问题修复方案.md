# 脚本模块问题修复方案

> 范围：`src/scripts/` 下的元素选取、回放执行、面板交互三块。
> 目标：解决三类长期影响可用性的问题。

---

## 一、现状概览

涉及的关键文件：

| 文件 | 职责 |
| --- | --- |
| [src/scripts/element-picker.js](src/scripts/element-picker.js) | 手动选元素的悬浮高亮 + Shift+点击候选 locator 弹窗 |
| [src/scripts/executor.js](src/scripts/executor.js) | 步骤回放，含元素查找、点击、等待 popup 等 |
| [src/scripts/locator-builders.js](src/scripts/locator-builders.js) | 多策略 locator 生成与匹配（id/css/xpath/...） |
| [src/scripts/selector-generator.js](src/scripts/selector-generator.js) | 旧 `Selector.generate / Selector.query` 兼容层 |
| [src/scripts/panel.js](src/scripts/panel.js) | 面板视图、列表/编辑器/运行/导入导出 |
| [src/scripts/recorder.js](src/scripts/recorder.js) | 录制状态机 |

数据形态：每一步的 `params` 同时存在三种 locator 字段：
- `targets`：`[[locator, builderName], ...]`，新格式（最稳）
- `selector`：单条主选择器（旧格式 / AI 默认产物）
- `selectorFallbacks`：旧格式的兜底列表

执行器统一入口是 [executor.js:10 `findByParams`](src/scripts/executor.js#L10)：先 `targets` 再退回 `selector + selectorFallbacks`，找到第一个就用。

## 二、问题与根因

### 问题 1 — AI 生成的脚本卡住，无法切换备选选择器

**现象**：AI 生成 `click` 一个 antd `select` 触发器、紧接着 `select`/`click option`。第一步如果点到外层壳子（不是真正的 trigger），下拉就不弹，后续 `wait` 直接超时；脚本至此不会自动切换到下一个候选 locator。

**根因**：
1. [executor.js:10 `findByParams`](src/scripts/executor.js#L10) 的策略是「找到第一个 DOM 命中就返回」，从未基于操作后的 UI 反馈决定要不要换一个。
2. [executor.js:357 `actions.click`](src/scripts/executor.js#L357) 调 `performClick` 后只调用 `waitForUiSettled()` 收尾，不关心是否真的弹出了 dropdown / dialog / listbox。
3. [executor.js:452 `actions.select`](src/scripts/executor.js#L452) 内部的 dropdown 等待用了 `.catch(() => null)` 静默吞错，给后续步骤埋雷。
4. [executor.js:40 `nudgeOpenDropdown`](src/scripts/executor.js#L40) 仅在 `waitForElement` 久等时尝试发一次 ArrowDown，覆盖不到「点错元素」的常见场景。
5. AI 输出经常只有 `selector` + `selectorFallbacks`，没有 `targets`，使得「多 locator 兜底」这条最稳的链路压根没生效。

### 问题 2 — Shift 弹出的候选 locator 弹窗，点击不生效也不关闭

**现象**：[element-picker.js:100 `_showPopup`](src/scripts/element-picker.js#L100) 弹出候选列表后，点击其中一行没有任何反应，弹窗也不关；只能 Esc 退出。

**根因**：捕获阶段事件顺序错位。
- [element-picker.js:35](src/scripts/element-picker.js#L35) 在 `document` 上挂了 capture 阶段 click 监听 `_onClick`。
- [element-picker.js:121](src/scripts/element-picker.js#L121) 又在 popup 节点上挂了 capture 阶段 click 监听。
- DOM 事件捕获阶段是**从外向内**：`document → … → popup li`。document 的 `_onClick` 必然**先**于 popup 节点上的监听器触发。
- 而 `_onClick` 第 86–87 行先调 `e.preventDefault(); e.stopPropagation(); e.stopImmediatePropagation();` 再判 `if (this.popup) return`。`stopPropagation` 拦掉了向 popup 节点的继续传播 → popup 自己的 click 监听**永远收不到事件**；同时 `_onClick` 自己也直接 `return`，啥也不做 → 弹窗既不能选也不会关。

### 问题 3 — 保存需要点多次"确定"才生效

**现象**：在编辑器里修改后点「保存」，会连续弹出多次 `已保存` alert，每次都要点确定；切换列表↔编辑器越多次，弹得越多。

**根因**：监听器逐次累积。
- 面板的 body / footer 容器是 `ensurePanel()` 里**只创建一次**的 DOM；后续 [panel.js:109 `setBody`](src/scripts/panel.js#L109) / [panel.js:115 `setFooter`](src/scripts/panel.js#L115) 只替换 `innerHTML`，容器本身始终是同一个 `<div>`。
- 但 [panel.js:329 `bindEditor`](src/scripts/panel.js#L329)、[panel.js:150 `renderList`](src/scripts/panel.js#L150)、[panel.js:171](src/scripts/panel.js#L171)、[panel.js:649](src/scripts/panel.js#L649)、[panel.js:751](src/scripts/panel.js#L751) 等每次进入视图都对**同一个**容器 `addEventListener('click', …)`，没有 `removeEventListener`。
- 每渲染一次视图就多挂一份 click 委托，旧的还在。点保存按钮，事件冒泡到 footer 容器 → 容器上累积的所有 click handler 全部依次触发。第 N 次进编辑器，保存逻辑会跑 N 次。
- [panel.js:403](src/scripts/panel.js#L403) `renderVarsList`、[panel.js:507](src/scripts/panel.js#L507) `paramsBox` input 监听等位置同样存在累积。

## 三、改造方案

### A. 执行器：基于"操作后果"的候选 locator 切换

目标：当一个步骤的语义是「打开下拉/弹层」时，命中元素并执行后能感知到 UI 没变化、自动切换下一个候选 locator 重试。

1. **在执行器引入 `tryWithCandidates(params, action)` 工具**（新文件 `src/scripts/candidates.js` 或加在 `executor.js`）：
   - 输入：`params`（含 `targets` / `selector` / `selectorFallbacks`）和一个返回 `{ ok, reason }` 的 `action(el)`
   - 候选顺序：`targets` 全部 → `selector` → `selectorFallbacks`，去重
   - 逐个尝试；一旦 `action` 返回 `ok=true` 立即返回，否则继续；全失败才抛错
2. **改 [actions.click](src/scripts/executor.js#L357) / [actions.select](src/scripts/executor.js#L452) / [actions.hover](src/scripts/executor.js#L490)**：
   - `click` 增加可选 `params.expect`：`'popup' | 'mutation' | 'none'`（默认 `none`）
   - 当 `expect === 'popup'` 或步骤后紧跟 `wait popupSelector` / `select` 类语义时，包一层 `expectPopupAppeared`：点击前快照 `document.querySelectorAll(POPUP_WAIT_SELECTOR)` 数量，点击后短轮询（300ms 起，最多 800ms）若数量未增 → 视为失败 → 触发候选切换
   - `select` 内部已有"点 trigger → 等 popup → 点选项"逻辑，把"点 trigger"那段委托给 `tryWithCandidates`，期望是 popup 出现
3. **AI 生成兜底**：在 [executor.js](src/scripts/executor.js) 的 `findByParams` 入口处，当只有 `selector + selectorFallbacks` 没 `targets` 时，自动包装成虚拟 targets 列表参与候选切换，无需改 AI 提示词
4. **可选**：`nudgeOpenDropdown` 保留作为兜底，但调用时机从 `waitForElement` 久等中迁出，改为 click 失败重试时按需触发一次

收益：AI/录制脚本里 trigger 选错时不再死等；用户已有的脚本不需要重写就能享受兜底。

### B. element-picker：合并 popup 点击处理到 document 监听

核心思路：**只保留一个全局 click 监听**，在它里面手动分流到 popup 处理 / 普通 finish。

具体改动 [element-picker.js](src/scripts/element-picker.js)：
1. 删除 `_showPopup` 内的 `popup.addEventListener('click', …, true)` 整块（第 121–129 行）。
2. 重写 `_onClick`：
   ```text
   _onClick(e):
     if (!active) return
     if popup 已存在:
       const li = e.target.closest('#webchat-script-picker-popup li[data-idx]')
       e.preventDefault / stopPropagation / stopImmediatePropagation
       if (li) → 用 li.dataset.idx 调 _finish(target, idx) 并清理 popup
       else if (e.target 在 popup 内) → 不做事（让用户继续看）
       else → popup.remove()，恢复 hover 选择（不 finish）
       return
     // 没 popup 的常规分支保持原样
     ...
   ```
3. `_onMove` 维持「popup 打开时不跟随鼠标」的现有判断。
4. 同时建议在 popup 上挂 `mousedown` 阻断（capture），避免一些页面的 `mousedown → focus → blur` 链反过来把 popup 顶掉。

收益：候选选择即刻可用；面板自然关闭；不会再误穿透到页面元素。

### C. panel：根除监听器累积

两条可选路线，**推荐 1**（改动最小、风险最低）：

**方案 1（推荐）— 每次 render 前 clone 容器以剥离旧监听器**

在 [panel.js](src/scripts/panel.js) 的 `setBody` / `setFooter` 内做"清洗"：

```text
function setBody(html):
  const old = panelEl.querySelector('.webchat-script-panel-body')
  const fresh = old.cloneNode(false)   // 不拷子节点也不拷监听器
  old.replaceWith(fresh)
  fresh.innerHTML = html
  return fresh
```

footer 同理。这样每次进入新视图，容器是全新的，旧的所有 click/input 监听都随旧节点一起被丢弃。

需要同步调整：所有 `panelEl.querySelector('.webchat-script-panel-body')` / `'.webchat-script-panel-footer'` 的引用必须重新取，不能缓存（目前实际就是每次取，无需大改）。

**方案 2 — 改成顶层事件委托**

在 `ensurePanel()` 内一次性挂 click/input/change 监听到 `panelEl`，用 `currentView` + `data-act` 路由到具体处理器。彻底解决累积问题，但需要重构 [panel.js:150 ~ panel.js:813](src/scripts/panel.js#L150-L813) 多处事件绑定逻辑。

无论选哪条，附带修复：
- `renderVarsList` 的 `wrap.addEventListener('input', …, { once: false })`（[panel.js:403](src/scripts/panel.js#L403)）改成在 `setBody` 之后只挂一次，或同样靠容器 clone 方式失效旧监听
- `paramsBox` 在 `editStepDialog` 中也存在同款风险（每次切换 type 重渲染 paramsBox），同步处理

收益：保存只触发一次；其他重复触发的 UI 行为（如变量被多次写入、步骤被反复添加）也一并消失。

## 五、验证方式

| 问题 | 手动验证 |
| --- | --- |
| 1 | AI 生成「点 antd select → 选项」步骤；故意把第一条 selector 改成它的外壳容器；执行应在 1s 内自动切换并成功 |
| 2 | 手动选元素时按住 Shift 单击，弹窗中点任意一行：应立即落到该 locator 并关闭 picker；弹窗外单击：弹窗关闭并恢复悬停选择 |
| 3 | 列表↔编辑器切换 5 次，再点保存：只弹一次"已保存"，存储里也只写一次（chrome.storage.local.get 校验） |

回归点：
- 录制流程不应受影响（不动 recorder）
- 既有脚本格式（`targets` / `selector` / `selectorFallbacks`）保持兼容，无需迁移
- `Esc` 取消选取流程不变
