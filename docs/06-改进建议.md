# 现有问题与改进建议

## 一、网页内容抓取的局限性

当前使用 `document.cloneNode(true)` + `innerText` 方案，存在以下问题：

### 问题

1. **动态内容遗漏** — SPA 应用中通过 JavaScript 动态渲染的内容可能未完全加载
2. **无法处理图片** — 只提取文本，图片中的信息完全丢失
3. **iframe 内容不可达** — 跨域 iframe 中的内容无法提取
4. **内容过长** — 大型页面提取的文本可能超出模型上下文限制，无截断策略
5. **结构信息丢失** — 纯文本丢失了标题层级、表格结构等语义信息

### 改进建议

1. **智能内容提取** — 使用 Readability.js（Mozilla 开源）提取正文，过滤广告和导航
2. **内容截断策略** — 根据模型上下文限制自动截断，优先保留用户可视区域内容
3. **结构化提取** — 保留 Markdown 格式的标题、列表、表格结构
4. **图片描述** — 提取 `alt` 属性，或调用多模态模型识别图片内容
5. **选区提取** — 允许用户选中页面部分内容作为上下文，而非全页提取

## 二、代码架构问题

### 问题

1. **content.js 过于庞大** — 1270 行代码包含 UI 创建、交互逻辑、通信、工具函数，职责不清
2. **popup.js 与 content.js 大量重复** — `initMarked()`、`addMessage()`、`handleUserInput()` 等逻辑高度相似
3. **无模块化** — 所有代码在全局作用域，无法复用
4. **硬编码字符串** — 提示文本、默认值散落各处

### 改进建议

1. **拆分 content.js** — 按职责拆分为：
   - `content/parser.js` — 网页内容解析
   - `content/dialog.js` — 对话框 UI
   - `content/ball.js` — 悬浮球 UI
   - `content/chat.js` — 聊天交互逻辑
2. **提取公共模块** — 将 popup 和 content 共享的逻辑提取到 `lib/` 下
3. **引入构建工具** — 使用 Vite/Webpack 支持模块化开发和打包
4. **常量集中管理** — 创建 `constants.js` 统一管理默认值和文本

## 三、API 通信问题

### 问题

1. **无请求超时** — fetch 请求没有超时机制，网络异常时会无限等待
2. **Token 估算不准确** — 使用 `字符数 / 4` 粗略估算，中文场景误差大
3. **无请求取消** — 停止生成时只断开 port，未取消 fetch 请求（后台仍在消耗 API 额度）
4. **错误信息不够友好** — API 返回的错误直接展示，用户难以理解
5. **无速率限制处理** — 未处理 429 Too Many Requests

### 改进建议

1. **AbortController** — 使用 AbortController 实现真正的请求取消
2. **请求超时** — 添加可配置的超时时间（默认 30 秒）
3. **Token 计算** — 使用 tiktoken 或类似库进行准确计算
4. **错误分类** — 区分网络错误、认证错误、限流错误，给出对应的用户提示
5. **重试策略** — 对可重试的错误（网络超时、限流）自动重试

## 四、用户体验问题

### 问题

1. **无对话管理** — 无法清空当前对话、无法导出对话记录
2. **无快捷键** — 缺少键盘快捷键支持
3. **无暗色模式** — 不适配暗色主题的网页
4. **对话框样式隔离不完全** — 部分网页的全局样式可能影响对话框
5. **移动端适配差** — 悬浮球和对话框在小屏幕上体验不佳

### 改进建议

1. **对话管理** — 添加清空对话、导出为 Markdown/JSON 的功能
2. **快捷键** — 支持 `Ctrl+Shift+Space` 打开对话框等快捷键
3. **主题适配** — 检测页面主题或提供暗色模式选项
4. **Shadow DOM** — 使用 Shadow DOM 完全隔离对话框样式
5. **响应式设计** — 小屏幕时对话框全屏显示

## 六、性能问题

### 问题

1. **全页面文本提取** — 大型页面提取全部文本耗时且浪费 Token
2. **无缓存机制** — 每次提问都重新提取页面内容
3. **MutationObserver 过于频繁** — 监听所有子树变化可能影响性能

### 改进建议

1. **增量提取** — 缓存页面内容，仅在页面变化时重新提取
2. **内容摘要** — 对长页面先生成摘要，用户追问时再提供详细内容
3. **节流 Observer** — 对 MutationObserver 回调添加节流处理
